# Сборка и выпуск UserNet

Android проверяет настроенный HTTPS-манифест с версией, ссылкой на APK и SHA-256. Приложение предлагает скачать пакет; установку подтверждает Android. Автоматической скрытой установки нет.

## Подготовка

1. Поднимите версию и числовой build в `pubspec.yaml`. UserNet — отдельное приложение (`com.userlay.usernet`), не обновление FlClashX. Профили и настройки автоматически не переносятся; аккаунт подключается отдельно по подписке. После первой установки обновления UserNet должны сохранять идентификатор пакета и ключ подписи.
2. Выполните анализ и тесты, соберите relay из совместимого checkout `vconnect`.
3. Выполните `USERNET_FLUTTER_BIN=/path/to/flutter scripts/build-usernet-release.sh stable`.
4. Скрипт читает ключ из локального приватного каталога. Не включайте ключ и пароль в Git или вывод команд.
5. Установите APK на тестовый телефон через `adb -s DEVICE_ID install -r PATH_TO_APK`. Не удаляйте предыдущую версию UserNet и не очищайте её данные.
6. Пройдите [условия готовности](release-readiness.md), включая длительный мобильный тест.

Если Gradle требует сеть при наличии всех зависимостей, допускается локальная сборка с `--offline`; это не способ обходить отсутствующие зависимости. Проверяйте фактический файл APK завершённой сборки.

## Публикация

Хост и каталог задаются только в частном окружении выпуска:

```sh
USERNET_RELEASE_HOST=account@release-host \
USERNET_RELEASE_DIR=/srv/usernet-updates/android \
  scripts/publish-usernet-android.sh stable VERSION BUILD \
  build/usernet-releases/usernet-stable-VERSION-BUILD.apk \
  'Описание изменений'
```

Скрипт сначала загружает версионный APK, затем атомарно заменяет манифест. Проверяйте скачивание и SHA-256 с отдельной сети. Не публикуйте незавершённую сборку.

## Windows

Предусмотрен отдельный манифест Windows, но готовность установщика и звонкового транспорта проверяется независимо. Поддержка звонкового транспорта на Windows пока не реализована.
