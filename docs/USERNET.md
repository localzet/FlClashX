# Архитектура UserNet

Mihomo — единственный движок политик маршрутизации, DNS и VPN. Звонковый адаптер Zorin Fabric предоставляет локальный SOCKS; он не заменяет исходную авторизацию пользователя на выбранной Remnawave-ноде.

```text
Приложения → Mihomo → выбранный прокси → выходная нода
                           ↓ при режиме Fabric
                    SOCKS 127.0.0.1:17890 → звонок → RU relay → выбранный прокси
```

RU relay переносит сокет. Учёт трафика, подписка, отзыв доступа и выбор исходной ноды остаются ответственностью Remnawave. API аккаунта обслуживается отдельно от доставки подписок; адрес подписки не заменяет авторизацию аккаунта.

## Режимы

- `auto`: выбор маршрута по доступности и настройкам клиента.
- `direct`: обычное подключение Mihomo без звонкового адаптера.
- `fabric`: подключение через звонок; при ошибке адаптера нет автоматического возврата на прямой прокси. Правила `DIRECT`/`REJECT` и исключения приложений в профиле продолжают действовать.

Личный выбор сохраняется в защищённом хранилище приложения и имеет приоритет над режимом профиля. Служебный блок удаляется перед передачей конфигурации Mihomo:

```yaml
usernet:
  enabled: true
  mode: auto
  socks-host: 127.0.0.1
  socks-port: 17890
  proxy-name: USERNET-CARRIER
```

В режиме Fabric прокси получают `dialer-proxy` локального адаптера. Уже заданные `dialer-proxy` сохраняются.

## Жизненный цикл

Контрольный звонок авторизует пользователя и выдаёт краткоживущую рабочую сессию. Затем клиент устанавливает отдельный рабочий звонок. Событие WebRTC ещё не доказывает передачу полезных данных: зелёный статус появляется только после HTTPS/JSON проверки API через SOCKS с проверкой сертификата Android. Это проверка в момент подключения, а не обещание непрерывной доступности.

Остановка и смена настроек отменяют старую операцию. Проверки поколения защищают состояние от событий завершённых процессов. Список доступных провайдеров приходит от backend; сейчас настроен Телемост, VK/WB не объявляются доступными без необходимых параметров.

## Надёжность и ограничения

Данные TCP передаются через KCP поверх VP8/RTP. У потоков независимые последовательности, но общий ограниченный видеоканал. Контроль перегрузки KCP и объединённые подтверждения снижают давление на очередь; повторная отправка выполняется самим KCP. При потере звонка соединения нужно устанавливать заново.

Доступность маршрутов зависит от сети. Первая привязка при полностью недоступном API не реализована. Перед массовым выпуском необходим длительный мобильный тест, смена сети и проверка остановки/восстановления.

## Безопасность

Токены, cookies, ссылки подписок, ключи подписи и конфигурация серверов не должны попадать в логи, скриншоты или Git.

Go-адаптеры проверяют TLS-сертификаты и имя сервера. На Android Go-процесс получает системные CA из Conscrypt APEX и системного каталога сертификатов. Проверка аккаунта и HTTPS-проверка готовности также проверяют сертификаты. Самоподписанный недоверенный сертификат отклоняется.

## Установка приложения

UserNet распространяется как отдельное приложение с идентификатором `com.userlay.usernet`; оно не заменяет FlClashX. Установка UserNet не удаляет и не меняет данные FlClashX. Локальные профили и настройки автоматически между приложениями не переносятся, аккаунт UserNet подключается отдельно по подписке. После первой установки UserNet его обновления должны сохранять идентификатор пакета и ключ подписи.
